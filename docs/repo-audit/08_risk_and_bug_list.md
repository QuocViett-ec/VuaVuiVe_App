# PHẦN 5 — PHÂN TÍCH RỦI RO VÀ DANH SÁCH LỖI (RISK & BUG LIST)

Tài liệu này tổng hợp các lỗi tiềm ẩn (chưa sửa trong code) liên quan đến cơ chế chạy (runtime), kiểu dữ liệu Firebase, đồng bộ UI, bảo mật, và cấu hình Gradle.

---

## Danh Sách Rủi Ro & Lỗi Tiềm Ẩn (Bảng Risk Matrix)

| Mức độ | Rủi ro | File liên quan | Mô tả lỗi | Ảnh hưởng | Cách kiểm tra | Đề xuất sửa chữa |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Critical** | **Lỗi ép kiểu số trên Firebase (Type Mismatch)** | `FirebaseOrderRepository.java`, `ProductRepositoryFirebase.java` | Firebase lưu trữ số không phân biệt số thực/số nguyên (đều là số). Nếu đọc số nguyên lớn bằng `Integer.class` hoặc số thực bằng `Double.class` mà trong database không khớp định dạng, app sẽ crash ngay lập tức vì `DatabaseException`. | Gây crash app đột ngột tại màn hình sản phẩm hoặc checkout. | Kiểm tra logcat khi tải dữ liệu số lượng kho hoặc giá tiền từ DB thực tế. | Đọc dữ liệu thô dưới dạng `Number` hoặc sử dụng wrapper an toàn: `Object val = snapshot.getValue(); if (val instanceof Number) return ((Number)val).intValue();`. |
| **Critical** | **Thiếu cấu hình Gán Shipper (Missing Order-Shipper Assignment)** | `MockRepository.java` (Admin), `FirebaseShipperRepository.java` (Shipper) | Admin App không ghi trường `shipperId` vào đơn hàng khi tạo Shipment. Shipper App lọc đơn theo `uid == order.getShipperId()`. | Shipper mở app lên sẽ không bao giờ thấy đơn hàng nào để giao. Luồng giao hàng bị tê liệt hoàn toàn. | Đăng nhập tài khoản Shipper và kiểm tra danh sách đơn giao (sẽ luôn trống). | Bổ sung trường chọn Shipper trong giao diện Admin khi xác nhận đơn hàng, cập nhật trường `shipperId` vào nút đơn hàng tương ứng. |
| **Critical** | **Lệch trường thông tin người nhận (Recipient Field Mismatch)** | `FirebaseShipperRepository.java` | Customer ghi đơn chứa `delivery_address`/`delivery_name`. Shipper lại đọc `recipient_address`/`recipient_name`. | Shipper không thấy tên, sđt, địa chỉ khách hàng. Không thể liên lạc hay đi giao. | Mở màn hình chi tiết đơn hàng trên Shipper App. | Thay đổi các khóa đọc trong hàm `mapSnapshotToOrder` của Shipper App trùng khớp hoàn toàn với Customer App. |
| **High** | **Lỗ hổng phân quyền Firebase Rules** | `database.rules.json` | Firebase Rules quy định quyền ghi đơn hàng của Shipper dựa trên biến `shipper_id` (`data.child('shipper_id').val() === auth.uid`). Tuy nhiên, trong code Java, field này được lưu là `shipperId`. | Quy tắc bảo mật bị vô hiệu hóa hoặc Shipper bị Firebase chặn quyền ghi cập nhật trạng thái đơn hàng. | Chạy thử tính năng cập nhật trạng thái đơn hàng trên app Shipper thực tế. | Cập nhật file `database.rules.json` thành: `data.child('shipperId').val() === auth.uid`. |
| **High** | **Lệch trường tên người dùng (User Profile Name)** | `MockRepository.java` (Admin), `FirebaseUserRepository.java` (Customer) | Khách hàng lưu tên là `full_name` khi đăng ký. Admin lại đọc trường `name` để hiển thị trên danh sách thành viên. | Khách hàng sẽ hiển thị không có tên (bị null/trống) trên màn hình quản lý thành viên của Admin. | Xem màn hình quản lý User trên Admin App. | Sửa code Admin `MockRepository` đọc tên người dùng: `String name = s.child("name").getValue(String.class); if (name == null) name = s.child("full_name").getValue(String.class);`. |
| **Medium** | **Thiếu hàm khởi tạo không tham số (No-Arg Constructor)** | Các file DTO trong `:shared` (như `User`, `Product`, `Order`) | Firebase Realtime Database SDK yêu cầu các lớp Java ánh xạ (Java Bean) bắt buộc phải có Constructor không tham số public và đầy đủ getter/setter để thực hiện deserialization. | Nếu lập trình viên bổ sung constructor có tham số mà quên constructor mặc định, app sẽ crash khi gọi `getValue(Product.class)`. | Kiểm tra toàn bộ các tệp DTO xem có constructor tùy biến nào không. | Đảm bảo luôn khai báo constructor rỗng: `public Product() {}` rõ ràng trong tất cả DTO. |
| **Medium** | **Trạng thái đơn hàng không đồng nhất (Status Case Inconsistency)** | `OrderListFragment.java` (Customer) | Màn hình lọc danh sách đơn hàng của khách hàng sử dụng mảng filter chữ thường (`"pending"`, `"cancelled"`), trong khi DB lưu trữ chữ in hoa (`PENDING`, `CANCELLED`). | Trạng thái hiển thị nhãn (Label) có thể bị lệch hoặc bộ lọc hoạt động sai. | Kiểm tra bộ lọc tab Đơn hàng bên phía Customer. | Đảm bảo luôn gọi `.toUpperCase()` hoặc `.toLowerCase()` trước khi so sánh chuỗi trạng thái giữa DB và UI. |
| **Low** | **Xung đột phiên bản Gradle (Gradle Dependency Conflict)** | `build.gradle.kts` các module | Các module `:app-customer`, `:app-admin`, và `:app-shipper` tự khai báo các phiên bản thư viện Firebase và Dagger Hilt riêng rẽ. | Dẫn tới lỗi build lúc biên dịch hoặc lỗi runtime không tương thích giữa các phiên bản. | Chạy lệnh `./gradlew dependencyInsight` hoặc build thử 3 ứng dụng. | Chuyển toàn bộ quản lý phiên bản dependencies dùng chung về file build.gradle.kts gốc hoặc dùng Gradle Version Catalog (`libs.versions.toml`). |
